# LTX動画作成メモ

## このメモについて

このメモは、LTXの公式情報や、Web上で共有されている使い方、実際に試して分かったことをもとにまとめたものです。

私自身もまだ試行錯誤中なので、ここに書いてある内容がすべて正しいとは限りません。環境やワークフロー、モデル、Seedなどによって結果も変わるようです。

「こうすると少しうまくいくみたいです」\
「こういう傾向があるようです」

くらいの参考メモとして見てもらえればと思います。

---

## 1. 解像度の目安

一般的によく使われる横長の解像度です。

| 呼び方 | 一般的な設定値 | LTXでの扱い |
|---|---:|---|
| 軽量 | 640 × 360 | 検証環境では640 × 320で出力された例あり |
| 720p / HD | 1280 × 720 | 検証環境では1280 × 704で出力された例あり |
| 1080p / Full HD | 1920 × 1080 | 内部条件に合わせて調整される可能性あり |
| QHD | 2560 × 1440 | 内部条件に合わせて調整される可能性あり |
| 4K / UHD | 3840 × 2160 | 内部条件に合わせて調整される可能性あり |

設定した解像度と完成動画の解像度が異なる場合があるようです。

> 解像度は32の倍数条件に合わせて自動調整されることがあるようです。

高解像度になるほど、必要なVRAM、生成時間、保存容量も増えるようです。最初は低めの解像度で動作や構図を確認して、良い結果が出てから高解像度化する方法もよさそうです。

※「2K」は用途によって指す解像度が違うため、このメモでは「QHD 2560 × 1440」と表記します。

## 2. 動作は時間順に書くと伝わりやすいようです

LTXでは、単語を並べるよりも、何がどの順番で起きるかを文章で書いた方が伝わりやすいようです。

基本的な流れは、次のような形です。

```text
開始状態
→ 最初の小さな動作
→ 主要動作
→ 髪・服・背景などの反応
→ カメラ移動
→ 最後の状態
```

例:

```text
少女は一瞬静止した後、ゆっくり顔を上げる。
画面を見ながらキーボードを打ち始める。
通知音が鳴ると手を止め、窓の方へ視線を移す。
カメラは少女の横顔へゆっくり近づく。
```

「少女、パソコン、タイピング、映画的」のような単語の並びよりも、開始から終了までの流れを書いた方が、意図を伝えやすいようです。

## 3. 動作を詰め込みすぎない方がよいようです

短い動画に動作をたくさん入れると、一つひとつが分かりにくくなったり、映像が崩れやすくなるようです。

3～5秒くらいの動画では、次のくらいが一つの目安になりそうです。

- 主要動作：1つ
- 補助的な小さな動作：1～2つ
- カメラ移動：1つ

例:

```text
主要動作：
少女がキーボードを打つ

補助動作：
通知音で手を止める
画面へ視線を向ける

カメラ：
顔へゆっくり近づく
```

次のように多くの動作を続けて入れると、短い動画では過密になるかもしれません。

```text
立つ
→ 歩く
→ 振り向く
→ 走る
→ ジャンプする
→ 着地する
```

複雑な場面は、一つの動画に詰め込まず、複数の短いクリップに分ける方法もよさそうです。

## 4. I2Vでは「次に起きること」を書くとよいようです

Image to Videoでは、人物の外見、服装、背景、構図などは、開始画像にすでに写っています。

そのため、画像の内容を詳しく説明するよりも、そのあと何が起きるかを書いた方がよいようです。

説明中心の例:

```text
白い服を着た少女が、窓のある部屋に立っている。
```

動作中心の例:

```text
少女はゆっくり窓の方を向く。
風が部屋に入り、髪と袖がわずかに揺れる。
少女が二歩前へ進む間、カメラは横から静かに追う。
```

変化させたくない特徴がある場合は、短く補足する方法もあるようです。

```text
服装と髪型は変化しない。
```

完全に固定されるとは限りませんが、特徴を保つ方向へ伝える補助にはなりそうです。

## 5. 感情はしぐさで書くと伝わりやすいようです

「悲しい」「不安」「怒っている」といった感情名だけでも意味は伝わりますが、映像として見えるしぐさに置き換えると、より具体的になるようです。

抽象的な例:

```text
少女は不安になる。
```

しぐさへ置き換えた例:

```text
少女は扉の方へ視線を移す。
唇に力を入れ、机の端を指で強く握る。
身体を少し縮めたまま、しばらく動かない。
```

感情を表現するときは、次のような要素が使えそうです。

- 視線の方向
- まばたき
- 眉や口元
- 指や手の動き
- 姿勢
- 呼吸
- 動作の速さ
- 動作の前後に置く「間」

抒情的な雰囲気を作る場合も、感情を直接説明するだけでなく、光、雨、風、環境音、カメラとの距離などを組み合わせると伝わりやすいようです。

## 6. カメラ移動は位置関係まで書くとよいようです

「カメラが動く」とだけ書くより、被写体に対して、どこからどのように動くかを書くと分かりやすいようです。

| 目的 | 日本語での指示例 |
|---|---|
| ゆっくり接近する | カメラは少女の顔へゆっくり近づく |
| 横から追う | カメラは肩の高さで横から人物を追う |
| 背後から追う | カメラは人物の背後からついていく |
| 固定する | カメラは固定したまま、人物だけが動く |
| 周囲を回る | 人物を中央に保ちながら周囲をゆっくり回る |
| 全体を見せる | 広い画角で部屋全体を捉える |
| 上から見せる | カメラは真上から場面を見下ろす |
| 肩越しに見せる | 人物の肩越しに画面を映す |

人物とカメラを両方大きく動かすと、うまくいかないことがあるようです。

最初は、

- 人物を大きく動かし、カメラは固定する
- 人物の動きを小さくし、カメラをゆっくり動かす

など、どちらかを控えめにすると扱いやすそうです。

## 7. 音声や環境音も書けるようです

LTXでは、映像だけでなく、セリフ、環境音、効果音、音楽などもプロンプトに含められるようです。

整理するときは、次の順にすると分かりやすそうです。

```text
環境音
→ 人物の声
→ 効果音
→ 音楽の有無
```

例:

```text
静かな雨音が窓を叩いている。
遠くを列車が通過する。
少女は小さく息の混じった声で話す。
音楽はない。
```

会話や音楽を避けたい場合:

```text
会話と音楽はなく、静かな室内音と雨音だけが聞こえる。
```

ただし、音声の有無や内容が、必ず指定どおりになるとは限らないようです。

### 日本語のセリフについて

漢字を含む日本語のセリフは、読み方が不安定になる場合がありました。

その場合は、文章全体ではなく、発話する部分だけひらがなにする方法が使えそうです。

```text
少女は小さな声で「どこに いったのかな」と話す。
```

これは公式仕様というより、実際に使ってみて分かった対策です。

## 8. Prompt Enhanceでは意図しない要素が加わることがあるようです

Prompt Enhanceは、短い入力をLTX向けの詳しいプロンプトへ補足・変換する機能のようです。

一般的には、次のように考えられます。

**Prompt Enhance OFF**

入力した文章を基準として生成する

**Prompt Enhance ON**

入力した文章を、より詳しい表現へ補足して生成する

Prompt EnhanceをONにすると、入力していない人物、場所、小物、動作、雰囲気などが補われることがあるようです。

元の入力プロンプトは保存されても、拡張後の文章そのものは保存されない場合があるようです。METAMIで確認したLTX 2.3公式ワークフロー由来の動画では、元の入力文とPrompt EnhanceのON／OFFは確認できましたが、拡張後の文章はMP4メタデータから確認できませんでした。

### 【実測メモ】

T2VでPrompt EnhanceをONにした際、カフェでコーヒーを飲み、スマートフォンを操作する男性が繰り返し出現した例がありました。原因は未特定です。

意図しない要素が出る場合は、次のような比較をしてみるとよさそうです。

- Prompt EnhanceをOFFにして比較する
- 同じ画像・同じSeedでON／OFFを比較する
- 入力プロンプトを少し具体的にする
- 出したくない要素を除外指定する

例:

```text
カフェは映さない。
コーヒーは登場しない。
スマートフォンを持たせない。
男性は登場しない。
```

Prompt Enhanceは便利ですが、入力していない要素まで足されることがあるようです。意図と違う結果が出た場合は、OFFとの比較をしてみるとよさそうです。

## 情報の区分

この作成メモでは、内容を必要に応じて次のように区別します。

### 公式情報

LTXの公式ドキュメント、公式リポジトリ、公式ワークフローなどで説明されている内容です。

### 一般的な作成Tips

公式情報や、広く共有されている使い方を参考にまとめた一般的な目安です。

### 実測メモ

METAMI開発中に、実際の動画やメタデータから確認した内容です。

### 経験則

特定の環境や、何度か使ってみて分かった傾向です。ほかの環境でも同じ結果になるとは限りません。

## 最後に

LTXでの動画生成には、一つだけの正解があるわけではなさそうです。

同じ画像、同じプロンプトでも、Seed、モデル、設定、ワークフローによって結果は変わるようです。

いろいろ試しながら、自分の環境でうまくいく方法を見つけていくのがよさそうです。
