# 05_AIツール別運用メモ

この文書は仕様ではなく、開発ツールごとの運用上の補足である。
アプリの要件は00〜04の文書を優先する。

## 共通方針
- 同じファイルをCodexとContinueに同時編集させない
- 比較するときはGitブランチ、worktree、または別コピーを使う
- AIの文章による完了報告より、実ファイルと実動作を優先する
- 作業開始前に正常動作版を保存する
- 失敗時は、禁止事項を大量に追加するより、作業範囲と完了条件を明確にする

## Codexに向く作業
- 初期実装
- 複数ファイルにまたがる機能
- プロジェクト全体の構成整理
- 原因調査と修復
- テスト作成
- 差分レビュー
- リファクタリング

Codexには、対象フォルダ、対象Ver、完了条件を示し、
内部設計はある程度委ねる。

## Continue＋ローカルモデルに向く作業
- 1〜数ファイルの明確な修正
- 日本語表示やラベルの変更
- 小さな機能追加
- READMEやドキュメント更新
- Codex版との比較実験

複雑な一括作業で不安定な場合は、対象を小さく分ける。

## Continueの推奨ツール設定
### Automatic
- read_file
- read_currently_open_file
- ls
- file_glob_search
- grep_search
- create_new_file
- edit_existing_file
- single_find_and_replace
- view_diff

### Ask First
- run_terminal_command
- 外部通信やURL取得
- 削除や環境変更を伴う操作

ツール名はContinueのバージョンにより多少異なる。

## Continueでの注意
- `Running`は必ずしも指示待ちではない
- `notepad.exe`等のGUIアプリをターミナルから起動すると、閉じるまでRunningが続く場合がある
- ファイル作成に失敗した場合、完了報告だけ生成されることがある
- 空ファイル、ファイルサイズ、実際の内容をPowerShellで確認すると確実

確認例:

```powershell
Get-Item .\src\main.py | Select-Object FullName, Length
Get-Content .\src\main.py
```

## Plus利用枠を意識した役割分担
- Codexの利用枠は、重要な基盤実装や難しい修正に使う
- 細かな変更はContinue＋ローカルモデルで行う
- Codexで正常な基準版を作り、Continueで派生版を試す
- 比較結果から採用版を決める
