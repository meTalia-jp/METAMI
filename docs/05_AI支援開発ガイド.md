# AI支援開発ガイド

## この文書の位置づけ

この文書は仕様書ではなく、M.E.T.A.M.I.の開発参加者に向けた、
AI開発ツールの使い分けに関する補足資料です。アプリの要件と仕様は、
`00`～`04`の文書を優先してください。

AI開発エージェントに共通するルール、完了条件、エラー対応、Git運用は、
[03_AI支援開発・Git運用ガイド.md](03_AI支援開発・Git運用ガイド.md)
を参照してください。

## ツールを使い分ける際の原則

- CodexとContinueに同じファイルを同時編集させない
- 実装を比較するときは、Gitブランチ、worktree、または別コピーを使う
- AIの文章による完了報告より、実ファイルと実際の動作を優先する
- 作業開始前に正常動作版を保存する
- 失敗を防ぐときは、禁止事項を増やしすぎず、作業範囲と完了条件を明確にする

共通のGit運用は、
[03_AI支援開発・Git運用ガイド.md](03_AI支援開発・Git運用ガイド.md)
に従います。

## Codexに向く作業

- 初期実装
- 複数ファイルにまたがる機能
- プロジェクト全体の構成整理
- 原因調査と修復
- テスト作成
- 差分レビュー
- リファクタリング

Codexへ依頼するときは、対象フォルダ、対象バージョン、完了条件を示し、
仕様の範囲内にある内部設計はある程度委ねます。

## Continue＋ローカルモデルに向く作業

- 1～数ファイルに限定された明確な修正
- 日本語表示やラベルの変更
- 小規模な機能追加
- READMEやドキュメントの更新
- Codex版との比較実験

複雑な一括作業で動作が不安定になる場合は、対象ファイルと完了条件を
小さく分けます。

## Continueの推奨ツール設定

### Automatic

- `read_file`
- `read_currently_open_file`
- `ls`
- `file_glob_search`
- `grep_search`
- `create_new_file`
- `edit_existing_file`
- `single_find_and_replace`
- `view_diff`

### Ask First

- `run_terminal_command`
- 外部通信やURL取得
- 削除や環境変更を伴う操作

ツール名はContinueのバージョンによって異なる場合があります。

## Continueでの注意点

- `Running`表示は、必ずしもユーザーの指示待ちを意味しない
- `notepad.exe`などのGUIアプリをターミナルから起動すると、閉じるまで`Running`が続く場合がある
- ファイル作成に失敗しても、完了報告だけが生成される場合がある
- 空ファイル、ファイルサイズ、実際の内容はPowerShellで確認すると確実

確認例：

```powershell
Get-Item .\src\main.py | Select-Object FullName, Length
Get-Content .\src\main.py
```

必要に応じて、Gitの状態と差分も確認します。

```powershell
git status --short
git diff --check
git diff
```

## クラウドAIとローカルAIの役割分担

- 重要な基盤実装や難しい原因調査は、プロジェクト全体を扱えるクラウドAIへ割り当てる
- 細かな修正や限定された実験は、Continue＋ローカルモデルへ割り当てる
- クラウドAIで正常な基準版を作り、ローカルAIで派生案を試す
- 実ファイル、差分、テスト、実動作を比較して採用版を決める

特定の料金プランや契約内容ではなく、作業の複雑さ、必要なコンテキスト、
データの取り扱い、利用できる実行環境に応じて役割を決めます。
