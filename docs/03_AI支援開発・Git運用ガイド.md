# AI支援開発・Git運用ガイド

## この文書の役割

この文書は、M.E.T.A.M.I.の開発でCodex、Continue、その他の
AI開発エージェントを利用する際の共通方針を定めます。
AIに必要な裁量を与えながら、仕様からの逸脱と、未検証の内容を含む
完了報告を防ぐことが目的です。

Codex、Continue、ローカルモデルの具体的な使い分けは、
[05_AI支援開発ガイド.md](05_AI支援開発ガイド.md)を参照してください。

## 最終判断の基準

本プロジェクトではコードを逐一確認するのではなく、実際の動作、
操作結果、画面表示を中心に最終判断します。主な確認対象は次のとおりです。

- 実際にアプリが起動するか
- 指定した操作ができるか
- 画面表示が要件どおりか
- AIによる日本語の説明が、確認結果と一致しているか

AIの報告は判断材料ですが、実ファイルと実際の動作を優先します。

## AI開発エージェントの基本ルール

1. 作業開始前に`docs/`内の関連仕様を確認する。
2. 指定されたバージョンの完了条件を満たすことを最優先にする。
3. 実装方法、内部設計、関数分割、例外処理、テスト追加は、合理的な範囲でAIが判断してよい。
4. 軽微な不足や矛盾は、既存仕様の目的に沿って判断して進めてよい。
5. 主要仕様の変更につながる場合は、作業前に確認または提案を行う。
6. 指定バージョンに必要な小規模修正は、関連ファイルを含めてまとめて実施してよい。
7. 既存コードが破損、空、または明らかに不適切な場合は、目的を保ったまま作り直してよい。
8. 実装後は、実際に変更したファイルを再確認する。
9. 実行可能な環境では、構文確認、テスト、または起動確認を行う。
10. 確認できていないことを「確認済み」「正常動作」と断定しない。

## 作業前の確認が必要な事項

次の変更は一律に禁止しませんが、着手前に必要性と影響を説明し、
確認を得ます。

- アプリの目的や主要機能の変更
- 対応形式や保存方式の変更
- 大きな外部依存関係の追加
- ユーザーファイルの変更または削除
- 仕様同士が明確に矛盾し、合理的に解決できない場合
- 既存ファイルの大幅な書き換え
- フォルダ構成の大きな変更
- 大規模なリファクタリング

テストコード、ログ、例外処理、UIの細かな改善など、指定された作業を
安全に完了するための小規模な関連修正は、影響範囲を限定して実施できます。

## 完了条件と報告

「完了」はファイルを変更しただけの状態ではなく、指定バージョンの
完了条件を満たし、実施可能な確認を終えた状態を意味します。

作業完了時は、日本語で次を報告します。

1. 実装・修正した内容
2. 変更したファイル
3. AIが実施した確認
4. ユーザーが行う動作確認
5. 未確認事項または残っている問題
6. 仕様外の改善案がある場合は、本文と分けた「提案」

確認できなかった項目は、その理由とともに未確認事項へ記載します。

## エラー対応

問題の調査では、可能な範囲で次の情報を使用します。

- エラーメッセージ全文
- 問題が起きる直前の操作
- 画面、対象ファイル、再現手順

AIは原因候補を挙げるだけで終わらず、影響範囲を確認し、可能な範囲で
修正します。修正後は再確認方法と、確認できていない項目を示します。

## Git運用

- 正常動作を確認できた状態を基準点としてコミットする
- AIの完了報告だけを根拠に正式な完了コミットを作らない
- 原則として、ユーザーによる動作確認後にコミットする
- 1つのバージョン、または意味のまとまった機能単位でコミットする
- 大きな変更の前には、正常動作版をコミットしておく
- 各バージョンの完了時に`docs/CHANGELOG.md`を更新する
- 複数のAI実装を比較するときは、同じ作業フォルダを同時編集せず、Gitブランチ、worktree、または別コピーを使用する
- コミット、タグ作成、pushは、依頼された範囲だけを対象にする

ツールごとの比較方法と注意点は、
[05_AI支援開発ガイド.md](05_AI支援開発ガイド.md)も参照してください。

## 共通実装依頼テンプレート

```text
docsフォルダの仕様を確認し、VerX.Xを実装してください。

仕様を満たすための内部設計や小規模な関連修正は、合理的に判断して進めてください。
主要仕様の変更や大きな依存関係の追加が必要な場合だけ、実装前に確認してください。

実装後は、変更ファイルを再確認し、可能な範囲で構文確認・起動確認を行ってください。
確認できていない内容を「確認済み」と報告しないでください。

最後に日本語で、変更内容、変更ファイル、実施した確認、
私が行う動作確認、未確認事項を報告してください。
Gitコミットは行わないでください。
```

## エラー修正テンプレート

```text
以下の問題を修正してください。

直前の操作:
（ここに記載）

エラーまたは現象:
（全文を記載）

関連する仕様を確認し、原因を調査して修正してください。
必要な関連修正は合理的な範囲で行って構いません。
修正後は変更ファイルを再確認し、確認できた内容と未確認事項を日本語で報告してください。
```
